  3. Toggle Intercept ON above, then browse / launch the app under test.
  4. Held requests appear in the Intercept tab — edit, then Forward or Drop.

Install & trust on iOS

  1. Tap Download CA Certificate above. Safari asks “This website is trying to download a configuration profile” → Allow.
  2. Settings → General → VPN & Device Management → PocketBurp Root CA → Install (enter passcode twice).
  3. Settings → General → About → Certificate Trust Settings → enable full trust for PocketBurp Root CA.
  4. Back in PocketBurp: Wi-Fi → Configure Proxy → Manual → Server 127.0.0.1, Port 8080.
  5. Open an HTTPS site in Safari. Requests now appear in HTTP History, decrypted.
⚠︎ Apps using certificate pinning (Banking, WhatsApp, most Google apps) will reject this CA — that is expected and normal, even with Burp on a laptop. Remove the profile and reset the Wi-Fi proxy when you are done testing.

How the trust flow works

PocketBurp generates certs/pocketburp-ca.key + pocketburp-ca.crt on first start (3072-bit key is unnecessary on a phone — 2048-bit RSA is used, valid 10 years). For every CONNECT host:443 it signs a fresh 397-day leaf certificate for that hostname (Apple's maximum), presents it to the client, and opens a real TLS connection to the server. Nothing leaves the device.
